## ポイント

- SEO・WordPressの実務経験を、現在の.NET開発につなげている
- Blazor Web App、ASP.NET Core、EF Core、PostgreSQL、BackgroundServiceを使用
- Gemini、検索API、X API、WordPress、Discordとの外部連携を実装
- Docker Compose + CaddyでVPS上の本番環境へデプロイ
- Playwright E2E Smoke Tests、Docker Container Smoke Tests、ヘルスチェックをCIで検証

- **Caddy**: リバースプロキシとしてTLSとヘルスチェックを担当
- **Blazor Web App**: 記事管理UIとIdentity認証を提供し、AI生成などの時間がかかる処理はBackgroundServiceの非同期ジョブへ分離
- **PostgreSQL**: 記事、ジョブ、設定データを永続化
- **外部連携**: Gemini（本文生成）、検索API・X API（情報収集）、WordPress（投稿）、Discord（通知）

## なぜこの技術構成か

- **Blazor Web App**: SEO・CMSの実務で蓄積したドメイン知識を、C#の型安全な環境で形にできる。サーバーサイドレンダリングとインタラクティブモードの使い分けが可能
- **PostgreSQL**: オープンソースで運用コストを抑えつつ、JSON型やフルテキスト検索など柔軟なデータ操作に対応
- **Docker Compose + Caddy**: VPS上の本番環境を、リバースプロキシ・TLS・ヘルスチェックまで含めてコードで管理
- **BackgroundService**: 記事生成やAPI連携を非同期ジョブとして分離し、UIの応答性を確保

## 技術判断

SEO・CMSの実務経験から生まれた要件を.NETで設計し、MVPの主要フローを実装して本番環境へデプロイしました。実装範囲と進捗は、完了条件を定義したバックログ（todo.md）で管理しています。

## ゲストログインの設計

公開環境は誰でも試せるようにしつつ、外部APIの費用発生や不正利用、WordPress・Discordへの意図しない送信は防ぐ必要があります。そこで、ゲストも通常ユーザーと同じ画面・処理を使い、外部との接続だけをサンプル応答へ切り替える設計にしました。

- 登録不要のゲストログインにもCSRF検証とログイン用のレート制限を適用し、Admin権限を持たない一般ユーザーとして作成
- 外部APIクライアントをユーザー単位でサンプル応答へ切り替え、Gemini・検索API・X API・WordPress・Discordの実APIには接続しない。バックグラウンドジョブでは、Cookieや入力内容に頼らず、DBに保存したジョブ所有者の情報からゲストかどうかを判定
- データはユーザーIDで分離し、セッションは永続化・延長なしの8時間。期限を迎えたゲストのアカウントと関連データは、バックグラウンド処理が1分ごとに確認して物理削除（処理中のジョブがある場合は完了後）

## 公開状況

[公開アプリ](https://web-writing.cloud/login)のログイン画面で「ゲストとして試す」を選ぶと、登録不要で主要機能を確認できます。ゲストモードの生成・検索結果はサンプルで、外部APIへの接続、WordPress投稿、Discord通知は行いません。ゲストのアカウントとデータは、利用開始から8時間後に自動削除されます。
